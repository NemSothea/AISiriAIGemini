# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

VoiceBank: a mock-data voice-banking demo, implemented three times — once per platform — with the same behaviour, names and fixtures. Each app exposes banking actions to that platform's native assistant (Siri / Gemini / Xiaoyi) plus an in-app on-device voice button. `PLAN.md` is the source of truth for scope, security tiers, phase status and open questions; update its roadmap status when a phase moves. (`AISiriAIGeminiPLAN.md` is an untracked older copy of the plan — don't edit it.)

Branding: the app stays "VoiceBank" with fictional data (payees "Dara", "Sokha", sample KHQR). Never introduce a real bank's name or logo.

## Commands

iOS (`ios/`, Swift 6, iOS 18+). The Xcode project is generated by XcodeGen from `ios/project.yml` and is gitignored — regenerate after adding/removing files:
```
cd ios && xcodegen generate
xcodebuild test -project ios/VoiceBank.xcodeproj -scheme VoiceBank -destination 'platform=iOS Simulator,id=<sim-id>'
# single test (Swift Testing): add -only-testing:'VoiceBankTests/VoiceCommandParserTests/publicCommands()'
```

Android (`android/`, Kotlin + Compose, minSdk 29, compile/target 37, AGP 9 + KSP):
```
cd android && ./gradlew :app:assembleDebug
cd android && ./gradlew :app:testDebugUnitTest
cd android && ./gradlew :app:testDebugUnitTest --tests 'com.example.voicebank.voice.VoiceCommandParserTest.<testName>'
adb shell am start -a android.intent.action.VIEW -d "voicebank://transfer?payee=Dara&amount=20"
```

HarmonyOS (`harmony/`, ArkTS, API 20+): open in DevEco Studio. **Never compiled** — written without DevEco, so expect ArkTS compiler errors and verify `[uncertain]` APIs against Huawei docs. See `harmony/README.md`. Deep-link test: `hdc shell aa start -A ohos.want.action.viewData -U "voicebank://..."`.

The only unit tests are the voice command parser tests (iOS + Android).

## Architecture (same shape on all three platforms)

```
Siri intent / Gemini AppFunction / Xiaoyi InsightIntent / deep link / in-app mic / touch
        │  (action name + params only)
        ▼
  BankAction / Route  ──► tier ──► AuthGate (biometric, +PIN for transfers) ──► screen
        │                                                                   │
        └────────────── AuditLog.record(source, action, tier, result) ◄────┘
```

- **Canonical action enum** — `ios/VoiceBank/App/BankAction.swift`, `android/.../BankAction.kt`, `harmony/.../services/Router.ets`. Each defines the same action names (`showQR`, `getRates`, `findBranch`, `checkBalance`, `freezeCard`, `prepareTransfer`), their tier, and parsing of `voicebank://qr|rates|branches|balance|freeze|transfer?payee=&amount=`. All entry points funnel into this enum, and opening an action writes an audit event. Adding an action means touching all three platforms: enum, deep link, assistant entry point, screen, parser.
- **Assistant entry points** — iOS: `Intents/` (`BankIntents.swift`, `PayeeEntity.swift` for saved-payee resolution, `VoiceBankShortcuts.swift` for phrases). Android: `appfunctions/BaseVoiceBankFunctionService.kt` (`@AppFunctionDeclaration`, KDoc is what Gemini reads; schema generated by KSP). Harmony: `entry/src/main/ets/intents/*Intent.ets`.
- **In-app voice** — `VoiceCommandParser` (rule-based, no LLM) + on-device STT (`VoiceListener` / `VoiceDialog`). Produces a `BankAction`.
- **Model** — `BankStore` / `BankRepository` load `mock_bank.json`. The fixture exists in three places (`ios/VoiceBank/Resources/`, `android/app/src/main/assets/`, `harmony/entry/src/main/resources/rawfile/`) and must stay byte-identical. Transfer-draft rules live here: saved payees only, 100 USD cap, 5-minute expiry, single use.
- **Security** — `AuthGate` per platform; demo PIN `1234`. Secure screens drop when the app backgrounds (re-auth on return); Harmony also sets window privacy mode.

## Security invariants (don't break these)

- Tier 1 (QR, rates, branches): may run and return data from the assistant without auth.
- Tier 2 (balance, freeze card): assistant entry point only opens the app; data shown in-app after biometric auth.
- Tier 3 (transfer): assistant only fills a draft; app requires review + biometric + PIN.
- Assistant responses/dialogs for Tier 2–3 must never contain balances, amounts, transactions or account numbers. AppFunctions run headless, so Tier 2–3 functions return only a PendingIntent / "opened app" result.
- Never via voice: new payees, limit/PIN/password changes, full account/card numbers.
- Audit log never stores balances.
